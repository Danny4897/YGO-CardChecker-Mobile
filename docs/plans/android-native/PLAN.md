# Android Native YGOChecker Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build an internally installable native Android app for the core YGOChecker loop: card search, persistent decklists, format legality, and contract-compatible text/YDKE import-export.

**Architecture:** A separate `android/` Gradle root uses multi-module Clean Architecture. Immutable models and repository ports point inward; Room/Retrofit/DataStore adapters point toward those ports; Compose features depend only on core modules; `app` is the composition root. UI follows Android list/detail and bottom-navigation conventions rather than cloning Angular layouts.

**Tech Stack:** Kotlin, Jetpack Compose Material 3, Navigation Compose, Hilt, Room, Retrofit/OkHttp, Coil, DataStore, Coroutines/Flow, JUnit, Truth, Turbine, Room in-memory tests, Compose UI tests, detekt, ktlint.

## Global Constraints

- Repository root: `C:\Users\adani\Desktop\YGOChecker`; Android Gradle root: `android/`.
- Branch: `refactor/android-native`.
- Build order: skeleton → core → data → features → APK.
- Application ID and namespace root: `com.ygochecker.android`.
- Internal version starts at `versionCode = 1`, `versionName = "0.1.0"`.
- Minimum SDK: 26; compile/target SDK and AGP/Kotlin/Compose versions are pinned to mutually compatible current stable releases in `android/gradle/libs.versions.toml`.
- Formats: `goat`, `edison`, `hat`, `tengu`, `tcg`; one global selection persisted with DataStore.
- Text contract: quantity/name lines; optional `#main`, `#extra`, `#side`; accept web aliases such as `3x Name`, `#!main`, and `Main Deck:`.
- YDKE contract: `ydke://<base64-main>!<base64-extra>!<base64-side>!`; passcodes are unsigned 32-bit little-endian values.
- Business failures return `AppResult.Err(errorKey)`; do not throw for expected import, lookup, persistence, or validation outcomes.
- Languages: English and Italian Android resources; system locale by default with an in-app override.
- First launch must search the packaged seed and open existing decks without network; card art may be absent offline.
- `feature:*` depends only on `core:domain`, `core:model`, `core:common`, and `core:designsystem`; it never depends on `data:*`.
- `data:*` implements ports declared in `core:domain`; only `app` binds implementations.
- The `feature:legality` module owns legality presentation/use-case integration but does not add a standalone v1 destination; editor badges and summaries are the mobile UX.
- Do not implement Assist, combo exploration, MDPro overlay/OCR, YgoFlow, a full offline pack, accounts, billing, or Play Store delivery.
- Do not copy the web page layout. Preserve only deck text, YDKE, section-placement, format, and error-contract behavior.

## Locked file/module map

```text
android/
  app/                         APK, Hilt bindings, root NavHost
  core/common/                 AppResult, AppErrorKeys, dispatchers
  core/model/                  immutable card/deck/format models
  core/domain/                 repository ports and one-action use cases
  core/designsystem/           duel theme and reusable Compose primitives
  data/cards/                  Room catalog, seed, API, banlist sync
  data/deck/                   Room decks, text/YDKE codecs
  data/preferences/            DataStore format/language settings
  feature/search/              search list/detail and quick-add
  feature/decklist/            deck list/editor/import-export
  feature/legality/            editor legality UI models/components
  feature/settings/            format/language/sync controls
  contracts/                   cross-platform golden fixtures
  tools/                       deterministic seed generator
```

The seed source is a normalized, committed JSON asset generated by `android/tools/generate_catalog_seed.py` from the existing card knowledge SQLite export when supplied via `--source`. The Android build never reads the developer SQLite database and never fetches a full catalog. The generator sorts by passcode, emits only fields required by v1, writes a SHA-256 manifest, and fails on duplicate/invalid passcodes. This makes the checked-in asset the reproducible input even when the local knowledge database is unavailable.

## Test strategy by module

- `core:common`: result mapping, error keys, dispatcher substitution; pure JVM tests.
- `core:model`: value constraints, max-copy semantics, Extra/Side placement; pure JVM property/table tests.
- `core:domain`: each use case against fakes; Turbine for Flow; no Android framework.
- `core:designsystem`: screenshot tests only after theme stabilizes; Compose semantics tests for shared controls.
- `data:cards`: deterministic generator tests, Room in-memory queries/migrations, MockWebServer sync failures, disconnected seed test.
- `data:deck`: Room transaction/reopen tests plus shared golden text/YDKE fixtures.
- `data:preferences`: DataStore persistence/default/corruption tests.
- `feature:search`: ViewModel reducer/Turbine tests and Compose list/detail/quick-add semantics.
- `feature:decklist`: ViewModel mutation/import/export tests and Compose editor ergonomics/accessibility.
- `feature:legality`: pure UI mapping tests and non-color status semantics.
- `feature:settings`: preference/sync ViewModel tests and Compose controls.
- `app`: Hilt graph compile test, navigation tests, and one core-loop instrumentation acceptance test.
- CI gate: module boundaries, JVM tests, Android lint, detekt, ktlint, debug APK; release assembly on protected/internal release runs.

## Explicit non-goals and guardrails

- No Assist recommendation scoring or script-synergy port.
- No combo explorer or combo-line authoring.
- No MDPro overlay, screenshot parsing, camera OCR, or accessibility overlay.
- No YgoFlow/effect-script engine.
- No web-layout clone, desktop card grid, persistent side panel, or modal-heavy interaction.
- No KMP/shared runtime in v1; golden fixtures are the compatibility boundary.
- No full offline image/catalog pack downloader; only the persisted disabled settings hook.
- No auth, cloud sync, billing, Play Store metadata, analytics, or push notifications.
